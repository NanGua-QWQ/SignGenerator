  `node_modules/.pnpm/typescript@7.0.2/node_modules/typescript/bin/tsc`，配 `-p tsconfig.json`。

用户反馈两点：① 没有道路等级底色；② 文本在画布显示很小、包围框却很大。

**① 道路等级底色（新功能）**

- store：`patchBaseplateAtom`；`sanitizeProject` 加 baseplate 消毒（旧存档兼容）。
- 画布：`CanvasGridBackground` 把牌面 `<rect>` 填充改成 `colorToCss(baseplate.color)`，
  `visible=false` 时用 `url(#baseplate-empty)` 棋盘格表示透明。
- UI：新建 `studio/BaseplatePicker.tsx`（等级预设按钮 + 自定义取色 + 显示底色开关），
  挂在 `page.tsx` 操作条（`flex-wrap`）。
- 代码生成：`java.ts` 新增 `buildBaseplateStatements()` —— 底色作为 `lines` 的**第一条**
  （最底层）：有贴图先铺铺满牌面的 `logo(...)`，再铺 `-rect w h` 纯色保险。

**② 文字太小 / 框太大**
- 根因：`ElementContent` 里 `fontSize = Math.max(4, 0.8 * element.scale * 20 * zoom)`。
  `0.8 * scale * 20` = **1 个文本像素**的高度，而一个字符占 `MC_FONT_HEIGHT`(=9) 个文本像素，
  所以字比包围盒小了约 9 倍。
- 修法：`fontSize = Math.max(1, MC_FONT_HEIGHT * unit)`（`unit = preview.unit * zoom`），
  并改为**逐字形 SVG 渲染**（用 `preview.glyphs` 的 `bx/by` 定位 + `textLength` 对齐单元格），
  位置与 `elementBox` 完全同源，彻底杜绝「框和字对不上」。
- `MC_FONT_HEIGHT` 从 `@/lib/studio/text` 导入。

tsc 零错误、`/`、`/signs`、`/signs/created` 全 HTTP 200。

### 修：选中框/框选框跟元素「跑边」错位（坐标原点不一致）
用户截图：网格牌面在右下、选中框却跑到左上角。根因是**三个图层锚点不同**：
- 元素层 `<div>` 有 `translate(calc(-50% + offset))` → 原点在画布中心；
- `SelectionOverlay` 用 `left=(cx-halfW)*zoom`（相对容器左上）却**渲染在元素层外面**，于是落到了画布左上角；
- `MarqueeRect` 曾用 `+ width/2` 手动补偿，与前者公式不一致。

**修法（根治）**：把 `MarqueeRect`、`SelectionOverlay` 一并**移入那个已平移的元素层容器**，
三者共用同一起点；`MarqueeRect` 去掉 `+width/2` 补偿，改用 `left = minX*zoom`、
`top = (height-maxY)*zoom`（与 `ElementView` 完全一致）。
另加 `zIndex`：选中框 20、框选框 30，保证始终画在元素（选中元素 z=10）之上。
删掉 `MarqueeRect` 已无用的 `width` prop。tsc 零错误，页面 HTTP 200。

**结论/约定**：画布内所有绝对定位图层必须挂在**同一个已平移容器**里；
坐标公式统一为 `left = x*zoom`、`top = (height - (y + h))*zoom`，禁止各自补偿 `width/2`。

### 再修：框选/元素/选中框整体错位（真正的根因 —— 坐标系没加中心偏移）
上面那条「统一到 `left=x*zoom`」是**错的**，把框选也带跑偏了。真正根因：
- 画布坐标约定是 **bit(0,0) = 牌面中心**（默认元素 x=0,y=0；与 Java `TextLineData.xOffset/yOffset` 一致），
  `screenToBit` 也是以「wrapRef 中心 + offset」为原点。
- 而那个已平移容器是 `pxW×pxH`、中心对齐到牌面中心，所以**容器左上角 = bit(-width/2, +height/2)**。
- `ElementView` 却用 `left=(cx-halfW)*zoom`（把容器左上当成 bit(0,0)），等于**整层少了中心的半宽半高**。
  之前网格是正确居中的、元素层偏了，所以看起来「元素/选中框跑到左上、网格在中间」——
  第一轮只挪容器没改公式，框选自然继续跑偏。

**正确公式（三处统一）**：
```
left = (width  / 2 + bitX - halfW) * zoom     // 元素/选中框
top  = (height / 2 - (bitY + halfH)) * zoom
// 框选矩形：left=(width/2 + minX)*zoom，top=(height/2 - maxY)*zoom
```
改了 `ElementView`、`SelectionOverlay`、`MarqueeRect`（`width` prop 重新加回），
`tsc` 零错误、页面 HTTP 200。

**教训**：改坐标系前先确认「bit(0,0) 到底在哪」。本项目 = 牌面中心，不是容器左上角。
