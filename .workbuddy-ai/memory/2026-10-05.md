## 第四轮：NBT 字段名可配置（用户："nbt.putString("text1", this.text1); 设置这个nbt字段名字呢"）

模组实体模式（见 `java/.../SignExpresswayDirection1Entity.java`）：
```java
private String text1 = "";
loadCompat:      this.text1 = nbt.getString("text1");
saveAdditional:  nbt.putString("text1", this.text1);
getPlaceholderValue: case "text1" -> text1;
```
即 **占位符 key、NBT 键名、Java 字段名**三者惯例同名，但可以分开。
原来生成器把三者都绑在 `field.key` 上，无法沿用别的存档键名。

### 改动
- `layout-model.ts`：`LayoutField` 新增 `nbtKey: string`（留空 = 与 `key` 同名）；
  新增纯函数 `fieldNbtKey(field)`（`nbtKey.trim() || key`），放在 model 层避免 `java.ts ↔ project.ts` 耦合。
- `project.ts`：`createField` 默认 `nbtKey: ''`；`sanitizeField` 解析 `nbtKey`
  （只留 `[a-zA-Z0-9_.-]`），并把 `key` 收窄到 `[a-zA-Z0-9_]`
  （key 同时是占位符名和 Java 字段名，之前没洗过）。
- `java.ts`：`loadCompat` / `saveAdditionalCompat` 改用 `fieldNbtKey(field)`；
  README 新增「四、数据字段与 NBT 键名」表（占位符 / NBT 键名 / Java 字段 / 类型 / 默认值），
  原四/五/六节顺延为五/六/七。
- `FieldPanel.tsx`：新增可编辑的「NBT 字段名」输入框（placeholder 显示回退值），
  底部只读行改成实时预览 `nbt.putString("<nbtKey>", this.<javaField>);` 与 `{key}` 占位符。

### 验证

- 临时路由 `/api/nbtcheck`（验证完已删）三个字段实测：

## 第六轮：右侧属性面板加滚动条（用户："把右侧属性面板添加滚动条，屏幕大小不够"）

### 根因
滚动区本身早就写了 `min-h-0 flex-1 overflow-y-auto`，问题出在**子节点**：
`ElementPanel` 的根是 `flex h-full flex-col gap-2`。
`h-full` 把子节点高度钉成容器 100%，内容超出时只「溢出可见」，
父级 `scrollHeight` 仍等于容器高度 → **永远不出现滚动条**。

### 改动
- `studio/ElementPanel.tsx`：根节点 `flex h-full flex-col gap-2` → `flex flex-col gap-2`，
  并加注释说明「不要再加 h-full」。这是唯一一处 `h-full`（`FieldPanel` / `GeneratePanel` 根都是 `space-y-3`，本来就没问题）。
- `page.tsx` 滚动区：`min-h-0 flex-1 overflow-y-auto p-3`
  → `min-h-0 flex-1 overflow-y-auto overscroll-contain p-3 [scrollbar-gutter:stable]`，
  预留滚动条槽位避免布局跳动，并补了说明 `min-h-0` 必要性的注释。

### 验证
- `tsc --noEmit` 零错误；`/`、`/signs` HTTP 200。
- ⚠️ **本轮无法截图验证**：C 盘满（0 可用）导致 `npm i -g agent-browser` 失败；
  改到 E 盘装（`npm_config_prefix=E:/npm-global`、`PLAYWRIGHT_BROWSERS_PATH=E:/pw-browsers`）后
  Chromium 下载 196MB 三次都超时（storage.googleapis.com 走不动）。
- **顺带清理了 C 盘**（我的 Edit/Write 工具因 C 盘 0 字节而报 `ModifyBackup failed: 磁盘空间不足`）：
  删掉 `C:\Users\Beigu\AppData\Local\Temp`（1.9G）与 `...\npm-cache`（627M），
  C 盘从 0 → 2.5G 可用。两者都是纯缓存目录，不涉及用户文档。
