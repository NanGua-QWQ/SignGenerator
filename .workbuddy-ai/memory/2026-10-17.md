# 2026-10-17

## 修 bug：生成出 `sign_expressway_.png` + 默认 `-rect`

用户报：生成/游戏里出现 `-texture yunbeiuc:textures/block/sign/sign_expressway_.png`，
并且「不是不要生成默认的 rect 吗」。

### 复现（临时路由 `/api/dbg`，已删）

| 场景 | 修前 | 修后 |
| --- | --- | --- |
| 新建贴图元素（不点图案库） | `logo("...sign_expressway_{logo}.png")` + **无 `logo1` 字段** | `private String logo1 = "national_logo_1";` |
| 字段 `logo1` 默认值为空 | `private String logo1 = "";` → 运行时拼出 `sign_expressway_.png` | 自动修正为 `national_logo_1` |
| 基板（默认） | `TextLineData baseplate = new TextLineData("-rect 32 20");` | **不产出** |
| 基板（手动打开） | 有 | 仍有（功能保留） |

### 三个根因

1. **`createLogoElement` 默认路径是假的**：`sign_expressway_{logo}.png` —— `{logo}` 不属于高速编号那一族
   （真模板是 `sign_expressway_{logo1}.png` / `sign_{logo}.png`），且新建元素时**不会**补字段
   （`ensureDynamicFieldsAtom` 只在图案库点选时触发）。
2. **没有任何地方保证字段默认值非空**：`createField` 默认 `defaultValue: ''`；
   `FieldPanel` 的「载入内置选项预设」Chip 只写 `options`、不动 `defaultValue`；
   改 key 也不动。于是实体里 `logo1 = ""`，`{logo1}` 被替换成空串 → `sign_expressway_.png`。
   模组渲染器对无效路径是**静默跳过整行**（`AbstractTextDisplayEntityRenderer` 里
   `textureExists` 为假就 `return`），不会回退成文本 —— 所以牌面上看到的 `-texture ...`
   只能是 `TextLineData.text` 原文，不是渲染兜底。
3. **基板 `visible` 默认 `true`**：`createBaseplate()` 直接给 `true`，所以每个新工程都带一层
   `-rect 32 20`（默认绿地）。用户要求默认不生成。

### 改动

- `lib/studio/project.ts`
  - 新增 `DEFAULT_LOGO_PATH = 'yunbeiuc:textures/block/sign/sign_expressway_{logo1}.png'`，
    `createLogoElement` 与 `sanitizeElement` 的兜底都用它（原来那个 `{logo}` 模板作废）。
  - `createBaseplate()` 默认 `visible: false`。
  - 新增 `ensureFieldsForPath(path, fields, name)`：缺字段 → 按 `optionGroupFor` 补 enum（含 `nbtKey`）；
    默认值空 → 用组默认值填；默认值不在选项里 → 退回第一个。
  - 新增 `repairPlaceholders(project)`：对所有**可见**元素的 path/text 跑一遍上面那个，只改字段不动元素，
    返回 `{ project, warnings }`。`sanitizeProject` 末尾也调用它（幂等），旧存档读进来就自愈。
- `lib/studio/java.ts`：`generateProject` 先 `repairPlaceholders` 再 `createContext`；
  `GenerationResult` 新增 `warnings: string[]`。
- `state/studio-store.ts`：`ensureDynamicFieldsAtom` 改走 `ensureFieldsForPath`（去掉重复实现，
  也删掉了 `findDynamicTexture`/`modFieldName`/`optionGroupFor`/`extractPlaceholderKeys` 的直import）；
  `addElementAtom` 新建元素后跑 `repairPlaceholders`，所以「加一个贴图」立刻带出 `logo1 = national_logo_1`。
- `studio/FieldPanel.tsx`：预设 Chip 在 `defaultValue` 不在新选项里时，顺手改成第一个选项值。
- `studio/GeneratePanel.tsx`：「生成结果」面板列出 `warnings`。

### 验证

`tsc -p tsconfig.json` 0 error；`GET /` 200；`node scripts/verify-dynamic-textures.mjs` 26 个文件全命中
（`sign_expressway_national_logo_1.png` 真实存在）。四个场景生成结果见上表。

⚠️ **用户已有存档**：里面的 `logo1` 还是 `""`，但载入时 `sanitizeProject` 会修，生成时再修一遍，
所以重新打开页面 / 重新生成即可，不用手工清 localStorage。

## 画布字体：取消拉伸 + 对齐游戏真实度量

用户报：每个字体都被横向拉伸、且字位置跟游戏里不符。

### 根因
- 画布用 SVG `textLength` + `lengthAdjust="spacingAndGlyphs"` 把每个字塞进固定格子 → 字宽≠格子宽被拉伸。
- 画布字宽用的是 MC 原版 `MC_CHAR_WIDTH` 表（如 `1`=6、`i`=2、`M`=6），与三个交通 TTF 真实 advance
  （re2014a `1`=3.37 / `i`=3.59 / `M`=7.26）完全不符 → 居中/位置全错。

### 改动
- `scripts/gen-font-metrics.mjs`（支持 cmap format 4 **和** 12；三套字体码位取**并集**，缺的记 -1 回落 MiSans）
  生成 `lib/studio/font-metrics.ts`（★自动生成勿手改★，换字体必重跑）。
- `lib/studio/text.ts`：
  - 删 `MC_CHAR_WIDTH`、旧 `charAdvance`/`measureTextWidth`；新增 `charMetric`（缓存，按模组 font json 的
    `size`/`shift` 算 em 与 baseline：交通 `em=10.5`、CJK `em=10.0*1000/1326=7.54`、`baseline=ascent-upem*em-shiftY`）、
    `sumAdvance`（逐字 raw，定位用）、`measureTextWidth`（**向上取整**，复刻 `Font#width` 的 `Mth.ceil`，
    对齐偏移 `renderX=-textWidth/2f` 必须跟这个一致）。
  - `PreviewGlyph` 改成 `{ char, left, baseline, em }`（去掉 x0/x1/y0/y1），`TextPreview.squeeze=unitX/unit`，
    `buildTextPreview` 按真实 advance 定位、字形自然宽度绘制。删掉死代码 `GlyphBox`。
- `studio/DesignCanvas.tsx` 文本分支重写：去掉 `textLength`/`lengthAdjust`；横向缩放统一走
  `<g transform="translate(anchorPx,0) scale(squeeze,1)">`，**支点取元素原点 `element.x`**
  （与模组 `translate→scale` 顺序一致，scaleX 只拉 renderX 之后的内容）。

### 验证（临时路由已删）
`tsc` 0 error；探针确认：三套字体 advance 与 TTF 实测一致；`even` 行最后一个字右边缘 = 包围盒右边缘；
`scaleX=2` 时第一个字渲染后左边缘 = 包围盒左边缘（squeeze 锚点正确）；`Left` 对齐首字在 `element.x`。
模组复算 `baseScale = 0.05*fontSize` ⇒ 1 文本像素 = 0.05*16 = 0.8*fontSize bit（旧 `0.8` 因子正确，保留）。

## 变体覆盖功能（元素 × 方块变体 的不同参数）

用户需求：「可以为其中一个文本行控件添加在不同方块变体的状态下的不同位置等参数」。

### 数据模型
- `LayoutElementBase.variantOverrides?: Record<variantId, Record<字段名, 标量>>`
- **只存被显式改过的字段**。早期版本想「开覆盖时把基础值全量种进去」，实测是个坑：
  面板「已覆盖 N 项」永远等于白名单长度，单项撤销也没意义了。合并读（缺省回退基础值）
  才是对的，`seedVariantOverride` 因此删除。
- 白名单 `OVERRIDABLE_FIELDS`（`lib/studio/variant.ts`）：text 20 个字段、logo 6 个、rect 6 个；
  `id/name/kind/variantOverrides` 永不覆盖。

### 读合并唯一入口
`applyVariantOverride(element, variantId)` / `applyVariantOverrides(list, variantId)`：
无覆盖时**返回同一引用**（画布/面板可以 `===` 判等，避免无谓重渲染）。
画布、属性面板（`previewElementsAtom`）、代码生成三处都过它，不会出现「画布看合并值、生成看原值」。

### 写路由
`patchElements(project, { id, patch, variantId })` 是唯一落点：
`variantId` 空 → 写本体；非空 → `setVariantFields` 只写 patch 里那几个键。
`updateElement / updateTextElement / moveElement / resizeElement / setElementAlignment` 都接受 `variantId`；
`page.tsx` 用 `patchElement / patchTextElement / move / resize / rotate / editText` 六个 wrapper 统一带上 `activeVariantId`。

### 代码生成
`buildVariantSwitch()`：仅当 `variants.length >= 2` 且至少一个元素有覆盖时才生成 switch，否则输出与以前逐字节一致。
分流依据 `BuiltInRegistries.BLOCK.getKey(...).getPath()`（一个工程多变体共用同一个方块类/实体，注册名是唯一稳定身份）。
**坑**：`buildVariantLines` 的 pad 要传 8 空格（语句自带 8 → case 体落 16），传 12 会多缩进 4 格。
**坑**：`buildVariantSwitch` 要传 `project.elements`（未过滤），可见性交给合并后的 `visible` 再筛 ——
否则「基础版式全隐藏、只在某变体显示」的元素会整个丢掉。
`hasLines = 可见元素 || 基板 || useVariantSwitch`，三处（构造函数 / loadCompat / 方法体）统一用它。

### UI
- 工具栏 `VariantSwitcher`（仅 `variants.length > 1` 渲染）：基础 + 各变体分段按钮。
- 属性面板 `VariantContext`：基础版式下给「切到变体」chips；某变体下显示「已单独设置 N 项」+
  每个字段一个可点撤销的 chip（`clearVariantField`）+「全部恢复基础」（`clearVariantOverride`）。
- 元素列表：有任一变体覆盖时点一颗 primary 小圆点；画布：该变体下有覆盖的元素描虚线框（`variantMarked`）。
- 只有一个变体时面板给一行灰字提示「去生成代码页加变体」。

### 验证（临时探针 `/api/dbgvariant`，已删）
base `x=0, scale=0.03` → v2 覆盖 `{x:12, scale:0.05}` → 合并 v2 = `{12, 0.05}`、合并基础 = `{0, 0.03}` 且同引用；
单项撤销后 keys=`["x"]`，整组撤销后 keys=`[]` 且 `variantOverrides` 属性消失；
生成的实体含 `switch (signVariantId) { case "sign_b" -> {...} default -> {...} }`，两分支数值正确、缩进 16 格。
`tsc` 0 error，`GET /` 200。
