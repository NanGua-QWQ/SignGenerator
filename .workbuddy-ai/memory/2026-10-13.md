# 2026-10-13

## 修复：桌面端预览面板下整站 JS chunk 被 403（跨源 dev 资源拦截）

**现象**（用户贴的 dev server 日志）：
```
⚠ Blocked cross-origin request to Next.js dev resource /_next/static/chunks/... from "127.0.0.1".
```
连 `/__nextjs_font/geist-latin.woff2`、`/_next/hmr` 都被拦，但 `GET / 200`。

**根因**：Next 16 的 `blockCrossSiteDEV`
（`next/dist/server/lib/router-utils/block-cross-site-dev.js`）在 dev 下默认只放行
`['**.localhost', 'localhost', <启动时的 hostname>]`。本项目 `next dev` 没带 `-H`，hostname = `localhost`，
所以 `localhost:3000` 能用，但**桌面端预览面板是用 `127.0.0.1:3000` 打开的** → 所有 `/_next/**`、`/__nextjs*`
一律 403 `Unauthorized`，页面本身 200 但 chunk 全挂 → hydration 直接失败（白屏/无交互）。
`warnOnce` 只对每条唯一消息打一次，所以日志里只看到 5 条。

匹配规则（`server/app-render/csrf-protection.js#isCsrfOriginAllowed`）：**只比 hostname，不带端口**；
先精确相等，再 `matchWildcardDomain`（`*` 匹配一段、`**` 只允许作最后一段，且不能匹配裸域名）。

**改动**：`next.config.ts` 加
```ts
allowedDevOrigins: ['127.0.0.1', '[::1]'],
```
（`[::1]` 是 IPv6 回环，走精确相等分支。）只影响 dev，生产构建不带这个开关。

**验证**（常驻 3000 服务，`next.config` 改动后 Next 自动重启了 dev server，PID 从 35004/11008 → 21148/47412）：
| Origin | 结果 |
| --- | --- |
| `http://127.0.0.1:3000` | 200 ✅（原 403） |
| `http://localhost:3000` | 200 |
| `http://[::1]:3000` | 200 |
| `http://evil.example.com` | 403 ✅（保护仍在） |

对真实 chunk `/_next/static/chunks/0jiw_next_dist_compiled_next-devtools_index_11grx1z.js` 测的。
`tsc -p tsconfig.json` 0 error，`GET /` 200。

复现命令：
```bash
curl -H "Origin: http://127.0.0.1:3000" -H "Sec-Fetch-Mode: cors" \
  "http://127.0.0.1:3000/<某 /_next/ chunk>"
```
